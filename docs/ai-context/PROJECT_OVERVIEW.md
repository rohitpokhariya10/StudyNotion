# Project overview and evidence register

Read [the master context](../../PROJECT_CONTEXT.md) first. Source wins over this audit and older ADRs.

## Scope and method

Audited on 2026-10-04 against `7b367c0`. The starting Git tree was clean, with 555 tracked files. Inventory covered every tracked path: 491 meaningful text/configuration files, 425 parsed JavaScript/JSX/TypeScript/tooling files, plus the lockfile and generated OpenAPI artifact. The remaining 62 files are visual/media assets, inventoried by path rather than treated as application logic. Dependency installations, Git internals, generated builds, private environment files, credentials, and binary contents were excluded. Environment example **names** and consumer validation were inspected; private environment values were not read.

Inspection combined recursive inventory, import/export/function/call analysis, direct source reading of implementation and configuration, route/model/contract cross-checks, test-case inspection, and a second documentation/source consistency pass. [FILE_MAP](FILE_MAP.md) is the per-file index, not a claim that static analysis can prove every runtime call. Runtime evidence and unexecuted checks are in [TESTING](TESTING.md). These documents describe the checked-out repository, not an account, cloud console, or running staging instance. The school-platform implementation-plan tab named in the IDE context is absent from this checkout and was not used as implementation evidence.

## Actual product and users

StudyNotion sells self-paced video courses. Anonymous visitors browse published courses, categories, public reviews, marketing pages, and policy pages. Students register, purchase, watch authorized lessons, track completion, review purchased courses, view purchase history, and request refunds. Instructors require approval before they can sign in and manage courses, curricula, thumbnails, video uploads, publishing, and revenue/enrollment dashboards. Admins approve or reject instructor registrations and handle payment/refund exceptions. The initial admin is provisioned through a controlled CLI; public signup does not accept Admin.

This is not currently a school SIS, multi-tenant organization platform, live classroom system, subscription service, chat system, or certificate engine. No corresponding runtime routes/models were found.

## What is already hardened

This checkout substantially exceeds a simple tutorial: revocable cookie sessions, policy gates, instructor approval, ownership checks, payment snapshots and replay protection, ambiguous-refund recovery, authenticated video delivery, rate limiting, environment validation, private operational checkpoints, and a large characterization/security test suite are implemented. Their guarantees and limits are documented in [SECURITY](SECURITY.md), not inferred from installed packages.
